# Accesibilidad — NEXUS V2.0

> **Estándar base:** WCAG 2.1 AA obligatorio en todo el ecosistema T1.
> **Objetivo:** WCAG 2.1 AAA donde sea técnicamente viable sin comprometer los tokens de color existentes del sistema.
>
> **Principio rector:** La accesibilidad no es una capa adicional — es parte del principio "Tecnología Humanizada". Un producto que no pueden usar todos los usuarios no es un producto completo.

## 1. Contraste y color

### Ratios mínimos WCAG

| Tipo de contenido | Ratio AA (obligatorio) | Ratio AAA (objetivo) |
|---|---|---|
| Texto normal (< 18px regular o < 14px bold) | 4.5:1 | 7:1 |
| Texto grande (≥ 18px regular o ≥ 14px bold) | 3:1 | 4.5:1 |
| Componentes de UI e íconos informativos | 3:1 | — (AAA no aplica a UI) |
| Texto decorativo o en logotipos | Sin requisito | Sin requisito |

### Pares de color del sistema — verificación de contraste

| Token de texto | Hex | Fondo | Hex | Ratio | AA | AAA |
|---|---|---|---|---|---|---|
| `color/brand/gray/800` | `#262626` | Blanco | `#FFFFFF` | 13.3:1 | ✓ | ✓ |
| `color/brand/gray/900` | `#1F2937` | Blanco | `#FFFFFF` | 14.7:1 | ✓ | ✓ |
| Oxford `#4C4C4C` | `#4C4C4C` | Blanco | `#FFFFFF` | 7.1:1 | ✓ | ✓ |
| `color/brand/gray/600` | `#525252` | Blanco | `#FFFFFF` | 6.3:1 | ✓ | ✓ |
| `color/brand/gray/500` | `#737373` | Blanco | `#FFFFFF` | 4.6:1 | ✓ | — |
| `color/brand/red/500` | `#DB3B2B` | Blanco | `#FFFFFF` | 4.8:1 | ✓ | — |
| `color/brand/red/900` | `#CC0000` | Blanco | `#FFFFFF` | 5.9:1 | ✓ | — |
| Blanco `#FFFFFF` | `#FFFFFF` | `color/brand/red/500` | `#DB3B2B` | 4.8:1 | ✓ | — |
| Blanco `#FFFFFF` | `#FFFFFF` | `color/brand/gray/800` | `#262626` | 13.3:1 | ✓ | ✓ |
| `color/brand/blue/500` | `#2180FF` | Blanco | `#FFFFFF` | 3.6:1 | ⚠️ | — |

> **Nota Blue 500:** `#2180FF` sobre blanco alcanza 3.6:1 — cumple AA **solo para texto grande y componentes UI**. No usar para body text normal (< 18px regular).

### Colores semánticos — pares verificados

| Semántico | Hex texto | Hex fondo | Ratio | AA | Notas |
|---|---|---|---|---|---|
| Success | `#4FC153` | `#F0FDF4` | 2.9:1 | ⚠️ | Solo íconos/UI, no texto normal |
| Error | `#CC0000` | `#FEF4F4` | 5.2:1 | ✓ | Apto para texto |
| Warning | `#FF6700` | `#FFF0E5` | 3.1:1 | ✓ | Solo texto grande o UI |
| Info | `#2180FF` | `#F0F8FF` | 3.4:1 | ⚠️ | Solo texto grande o UI |
| Disabled | `#A3A3A3` | `#F2F2F2` | 1.9:1 | — | Decorativo intencional |

> **Disabled es intencional:** El bajo contraste comunica visualmente que el elemento no está disponible. Debe complementarse siempre con `cursor: not-allowed` y `aria-disabled="true"` para no depender solo del color.

### Reglas de uso de color

| Regla | Descripción |
|---|---|
| No comunicar solo con color | Toda información transmitida por color debe tener respaldo en texto, ícono o patrón visual |
| Éxito / Error / Warning | Siempre acompañar el color semántico con ícono y texto descriptivo |
| Texto sobre fondos de color | Verificar contraste caso por caso cuando el fondo no sea blanco o gris claro |
| Modo oscuro (dashboard) | Los tokens de dark mode en Figma deben verificarse independientemente — ver `foundation/THEMES.md` |

## 2. Focus states y navegación por teclado

### Regla global de focus

**Todo elemento interactivo debe mostrar un focus state visible** cuando recibe foco por teclado. Esta es una regla de implementación obligatoria en NEXUS — no negociable.

| Propiedad | Valor |
|---|---|
| Color del outline | `#2180FF` |
| Grosor | `2px` |
| Offset | `2px` |
| Cuándo mostrar | Solo con navegación por teclado (`focus-visible`), no con click de mouse |

### Focus por tipo de componente

| Componente | Estilo de focus | Notas |
|---|---|---|
| Botón primario | Outline `#2180FF` 2px, offset 2px | Sobre cualquier fondo |
| Botón secundario | Outline `#2180FF` 2px, offset 2px | Mismo estilo que primario |
| Botón icon-only | Outline `#2180FF` 2px, offset 2px | Área mínima 44×44px incluida |
| Input / Textarea | Border `#2180FF` reemplaza border gris | Consistente con estado focus del input |
| Link | Outline `#2180FF` 2px, offset 2px | Underline adicional en hover |
| Checkbox / Radio | Outline `#2180FF` 2px alrededor del control | No alrededor del label |
| Switch | Outline `#2180FF` 2px alrededor del track completo | |
| Tab (pill) | Outline `#2180FF` 2px, border-radius heredado | |
| Item de sidebar | Outline `#2180FF` 2px, offset interno | |
| Card interactiva | Outline `#2180FF` 2px, offset 2px | Solo si la card es clickable |
| Dropdown / Select | Outline `#2180FF` 2px al abrirse | |
| Fila de tabla clickable | Outline `#2180FF` 2px en la fila | |

### Orden de tabulación

| Regla | Descripción |
|---|---|
| Flujo natural | El orden de Tab sigue el flujo visual: izquierda → derecha, arriba → abajo |
| `tabindex` positivos prohibidos | Valores > 0 rompen el orden natural del DOM |
| `tabindex="0"` | Solo para hacer focusable un elemento no-interactivo por defecto |
| `tabindex="-1"` | Para elementos que reciben focus programáticamente (ej. modal al abrirse, mensaje de error al validar) |
| Elementos ocultos | `display: none` y `visibility: hidden` quedan fuera del tab order automáticamente |

### Navegación por teclado esperada

| Componente | Teclas requeridas |
|---|---|
| Botones / Links | `Enter`, `Space` para activar |
| Inputs de texto | `Tab` / `Shift+Tab` para entrar y salir |
| Select / Dropdown | `Enter` o `Space` para abrir · `↑↓` para navegar · `Enter` para seleccionar · `Esc` para cerrar |
| Tabs / Pills | `←→` para moverse entre tabs · `Enter` para activar |
| Modal | `Esc` para cerrar · foco atrapado dentro mientras está abierto |
| Sidebar (items) | `↑↓` para navegar · `Enter` para activar · `→` para expandir sección |
| Checkbox group | `Space` para toggle · `Tab` para siguiente |
| Radio group | `↑↓` o `←→` dentro del grupo |
| Datepicker | `←→↑↓` para navegar días · `Enter` para seleccionar · `Esc` para cerrar |

### Focus trap en modales

Cuando un modal está abierto, el foco debe quedar atrapado dentro del modal hasta que se cierre. Al cerrarse, el foco debe regresar al elemento que abrió el modal.

## 3. ARIA — expectativas por componente

> **Importante:** Esta sección documenta qué atributos ARIA **debe tener** cada componente. No describe el estado actual de implementación — es el estándar al que deben llegar todos los componentes del ecosistema T1.
>
> **Prioridad siempre:** HTML semántico correcto antes de ARIA. ARIA complementa cuando el HTML nativo no es suficiente.

### Botones

| Situación | Atributos requeridos |
|---|---|
| Botón con texto visible | Sin atributos adicionales |
| Botón solo con ícono | `aria-label` con descripción de la acción |
| Botón en estado cargando | `aria-disabled="true"` + `aria-busy="true"` |
| Botón que abre modal | `aria-haspopup="dialog"` + `aria-expanded` |
| Botón de toggle (ej. favorito) | `aria-pressed="true/false"` |

### Inputs y formularios

| Elemento | Atributos requeridos |
|---|---|
| Todo input | `id` + `<label for="">` asociado |
| Input con error | `aria-invalid="true"` + `aria-describedby` apuntando al mensaje de error |
| Input con helper text | `aria-describedby` apuntando al helper text |
| Campo requerido | `required` + `aria-required="true"` |
| Grupo de campos relacionados | `<fieldset>` + `<legend>` |
| Grupo de radio buttons | `<fieldset>` + `<legend>` |

### Tablas de datos

| Elemento | Atributos requeridos |
|---|---|
| `<table>` | `aria-label` con descripción del contenido |
| `<th>` de columna | `scope="col"` |
| `<th>` de fila | `scope="row"` |
| Columna ordenable | `aria-sort="ascending/descending/none"` en el `<th>` activo |
| Botón de ordenamiento | `aria-label` descriptivo del cambio que realizará |

### Modales y diálogos

| Atributo | Valor requerido |
|---|---|
| `role` | `"dialog"` |
| `aria-modal` | `"true"` |
| `aria-labelledby` | ID del heading principal del modal |
| `aria-describedby` | ID del párrafo descriptivo (cuando aplique) |
| Botón de cierre | `aria-label="Cerrar"` |

### Navegación y sidebar

| Elemento | Atributos requeridos |
|---|---|
| `<nav>` principal | `aria-label="Navegación principal"` |
| Link activo (página actual) | `aria-current="page"` |
| Sección colapsable | `aria-expanded="true/false"` en el botón trigger |
| Lista de nav items | `role="list"` en `<ul>` |

### Toasts y notificaciones

| Tipo | Atributos requeridos |
|---|---|
| Success / Info | `role="status"` + `aria-live="polite"` + `aria-atomic="true"` |
| Error crítico | `role="alert"` + `aria-live="assertive"` + `aria-atomic="true"` |
| Warning | `role="status"` + `aria-live="polite"` |

> **Regla:** `aria-live="assertive"` interrumpe al lector de pantalla inmediatamente. Usarlo solo para errores que bloquean al usuario — no para notificaciones informativas.

### Íconos

| Situación | Atributos requeridos |
|---|---|
| Ícono decorativo (acompañado de texto) | `aria-hidden="true"` + `focusable="false"` |
| Ícono informativo (sin texto) | `role="img"` + `aria-label` descriptivo |

### Badges y estados visuales

| Situación | Atributos requeridos |
|---|---|
| Badge con texto visible | Sin atributos adicionales |
| Badge de contador (ej. "3 sin leer") | Incluir texto completo en `aria-label` del botón padre |
| Punto de color como indicador de estado | `aria-label` en el elemento contenedor |

## 4. Touch targets y accesibilidad móvil

### Tamaño mínimo de touch targets

**Regla WCAG 2.5.5 (AA):** Todo elemento interactivo debe tener un área táctil de al menos **44 × 44 px**.

| Componente | Alto visual | Área táctil mínima | Cómo lograrlo |
|---|---|---|---|
| Botón primario / secundario | 45px | 45px ✓ | El alto natural lo cumple |
| Botón icon-only | ~40px | 44 × 44px | Padding que amplíe el área táctil |
| Link en navegación | Variable | 44px alto | Padding vertical generoso |
| Checkbox / Radio | 20px el control | 44px área | Hacer clickable el label completo |
| Switch | 24px alto | 44px área | Padding vertical en el contenedor |
| Item de lista o tabla | ~40px | 44px mínimo | `min-height: 44px` |
| Tab pill | ~36px | 44px alto | Padding vertical en el tab |
| Botón cerrar modal | 24px ícono | 44 × 44px | Padding que amplíe el área táctil |
| Item de menú dropdown | ~36px | 44px alto | Padding interno del item |

### Espaciado entre elementos táctiles

Mantener al menos **8px de separación** entre elementos interactivos adyacentes para evitar activaciones accidentales.

### Viewport — regla obligatoria

| Configuración | Estado |
|---|---|
| `user-scalable=no` en viewport meta | **Prohibido** — impide el zoom para usuarios con baja visión |
| `maximum-scale=1` en viewport meta | **Prohibido** — mismo efecto que user-scalable=no |
| Zoom del navegador | Nunca bloquear — las interfaces de T1 deben funcionar al 200% de zoom |

### Gestos y alternativas

| Gesto | Alternativa requerida |
|---|---|
| Swipe para eliminar | Botón de eliminar visible o menú contextual |
| Pull to refresh | Botón "Actualizar" visible |
| Pinch to zoom en contenido | No bloquear el zoom del browser |

### Orientación

Las interfaces de T1 deben funcionar tanto en portrait como en landscape. No bloquear orientación de pantalla salvo casos excepcionales documentados y justificados.

## 5. Lectores de pantalla y texto alternativo

### Reglas para imágenes

| Tipo de imagen | Qué incluir en `alt` |
|---|---|
| Imagen informativa | Descripción del contenido relevante para el contexto |
| Imagen decorativa | `alt=""` + `aria-hidden="true"` |
| Logo de T1 o producto | Solo el nombre (`alt="T1"`, `alt="T1tienda"`) |
| Logo de marca tercera (carrier, banco, red social) | Solo el nombre de la marca (`alt="FedEx"`, `alt="DHL"`) |
| Screenshot de UI en landing | Describe la funcionalidad visible, no el diseño visual |
| Gráfica / chart | Descripción del dato principal o tendencia más relevante |
| Imagen de producto | Nombre, característica principal y estado de stock si es relevante |
| Código QR | Para qué sirve el QR (`alt="Código QR para descargar la app de T1"`) |
| Bandera de país | Nombre del país (`alt="México"`) |
| Imagen de persona (decorativa) | `alt=""` |

### Guía de texto alternativo para contexto T1

| Contexto | Ejemplo correcto | Ejemplo incorrecto |
|---|---|---|
| Screenshot del dashboard | `alt="Vista del panel de pedidos con 3 órdenes pendientes"` | `alt="Captura de pantalla"` |
| Gráfica de ventas | `alt="Gráfica de ventas enero-marzo 2026 con tendencia positiva del 23%"` | `alt="Gráfica"` |
| Logo T1 en header | `alt="T1"` | `alt="Logotipo de T1 color rojo"` |
| Producto en catálogo | `alt="Camiseta básica azul marino talla M, en stock"` | `alt="Producto"` |
| Ícono decorativo en botón | `aria-hidden="true"` (sin alt) | `alt="ícono"` |

### Texto visible vs texto para screen readers

| Situación | Manejo correcto |
|---|---|
| Texto solo para screen readers | Clase `sr-only` — accesible pero invisible visualmente |
| Texto visible que no aporta a lectores | `aria-hidden="true"` en el elemento |
| Contador numérico en badge | El botón padre incluye el conteo en su `aria-label` |
| Asterisco de campo requerido | El `*` visible lleva `aria-hidden="true"` · el label incluye "(requerido)" con `sr-only` |

### Gráficas y visualizaciones de datos

| Alternativa | Cuándo usar |
|---|---|
| `aria-label` en el contenedor con resumen del dato principal | Siempre como mínimo |
| `<figcaption>` visible con descripción | Para gráficas con datos críticos de negocio |
| Tabla de datos alternativa (puede ir con `sr-only`) | Para gráficas complejas con múltiples series de datos |

### Formularios complejos

| Elemento | Requisito |
|---|---|
| Grupo de campos relacionados (ej. dirección de envío) | `<fieldset>` + `<legend>` descriptivo |
| Grupo de radio buttons | `<fieldset>` + `<legend>` que describa la pregunta |
| Stepper / wizard multi-paso | Indicar paso actual con `aria-current="step"` o texto visible |
| Campos de fecha compuestos | Cada sub-campo (día, mes, año) tiene su propio label |

### Actualizaciones dinámicas de contenido

| Tipo de actualización | Implementación |
|---|---|
| Resultados de búsqueda o filtro | Región `aria-live="polite"` que anuncie cuántos resultados se encontraron |
| Contador en tiempo real (ej. pedidos pendientes) | `aria-live="polite"` en el contenedor del número |
| Mensajes de error en formularios | `role="alert"` o `aria-live="assertive"` |
| Notificaciones de sistema | `aria-live="polite"` para info/éxito · `aria-live="assertive"` para errores críticos |

### Reducción de movimiento

Respetar la preferencia del sistema operativo del usuario mediante `prefers-reduced-motion`:

| Animación | Comportamiento normal | Con `prefers-reduced-motion: reduce` |
|---|---|---|
| Fade de sección / página | Opacity 0→1, 300ms | Sin transición — mostrar directamente |
| Slide de modal / drawer | Translate + fade, 250ms | Sin slide — mostrar directamente |
| Spinner de carga | Rotación continua | Spinner estático o texto "Cargando..." |
| Carrusel con autoplay | Transición automática cada X segundos | Detener autoplay, solo navegación manual |
| Smooth scroll | Desplazamiento animado | Scroll instantáneo |
| Skeleton shimmer | Animación wave de fondo | Fondo estático sin animación |
| Hover scale en cards | `scale(1.02)` al hacer hover | Sin escala — solo cambio de sombra o borde |
| Animaciones `data-animate` en landing | Slide-right / scale al entrar al viewport | Sin animación — mostrar directamente |

> **Animaciones que pueden mantenerse activas con `prefers-reduced-motion`:** barras de progreso con valor real, cambio de estado de toggles on/off, aparición de mensajes de error/éxito inline. Estas son informativas, no decorativas.

## 6. Reglas obligatorias — resumen

Las siguientes reglas son de implementación obligatoria en todo componente y pantalla del ecosistema T1.

| # | Regla | Nivel |
|---|---|---|
| 1 | Focus state visible: outline `#2180FF` 2px, offset 2px en todos los elementos interactivos | AA |
| 2 | Nunca usar `focus: outline-none` sin un focus style custom equivalente | AA |
| 3 | Todo elemento interactivo: touch target mínimo 44 × 44 px | AA |
| 4 | Contraste mínimo 4.5:1 para texto normal · 3:1 para texto grande y componentes UI | AA |
| 5 | Nunca comunicar información solo con color | AA |
| 6 | Todo ícono standalone sin texto visible: `aria-label` descriptivo | AA |
| 7 | Todo ícono decorativo: `aria-hidden="true"` + `focusable="false"` | AA |
| 8 | Todo input tiene `<label>` asociado o `aria-label` | AA |
| 9 | Inputs con error: `aria-invalid="true"` + `aria-describedby` apuntando al mensaje | AA |
| 10 | Modales: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, focus trap activo | AA |
| 11 | Imágenes informativas: `alt` descriptivo · Decorativas: `alt=""` + `aria-hidden="true"` | AA |
| 12 | Respetar `prefers-reduced-motion` — animaciones no esenciales desactivadas | AA |
| 13 | Viewport: prohibido `user-scalable=no` y `maximum-scale=1` | AA |
| 14 | Tab order sigue el flujo visual natural · Prohibido `tabindex` con valores positivos | AA |
| 15 | Todos los flujos principales deben ser completables solo con teclado | AA |
| 16 | Gráficas y visualizaciones: alternativa en texto o tabla siempre presente | AA |

### Anti-patterns críticos

| Anti-pattern | Problema | Corrección |
|---|---|---|
| `focus: outline-none` sin reemplazo | Hace la interfaz innavegable por teclado | Siempre definir un focus style visible |
| Botón icon-only sin `aria-label` | El lector de pantalla anuncia "button" sin contexto | Agregar `aria-label` con la acción |
| Error de formulario solo con color rojo | Usuario daltónico no puede identificar el error | Agregar ícono + texto descriptivo del error |
| `user-scalable=no` en viewport | Bloquea el zoom para usuarios con baja visión | Eliminar — las interfaces de T1 deben soportar zoom al 200% |
| Touch target menor a 44px | Dificulta la interacción en móvil | Ampliar área táctil con padding |
| Imagen informativa sin `alt` | El lector de pantalla no transmite la información | Agregar `alt` descriptivo del contenido relevante |
| `aria-live="assertive"` en notificaciones de éxito | Interrumpe al lector de pantalla innecesariamente | Usar `aria-live="polite"` para info y éxito |
| Animaciones sin `prefers-reduced-motion` | Puede causar malestar en usuarios con vestibular disorders | Implementar media query de reducción de movimiento |
